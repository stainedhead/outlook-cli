## Graph endpoint shapes assumed by the adapter (all UA-1)

Every endpoint is `/v1.0/me/...`; `/users/{id}` is never used. All shapes below are unverified against a real tenant.

| Port method | Request | Assumed behaviour |
|---|---|---|
| Me | `GET /me?$select=mail,userPrincipalName` | `mail` may be null; the UPN then identifies the mailbox |
| ListFolders | `GET /me/mailFolders?$top=100&$select=id,displayName,unreadItemCount,totalItemCount`, follows `@odata.nextLink` | top-level folders only; the well-known flag comes from `GET /me/mailFolders/{alias}?$select=id` for inbox, drafts, sentitems, deleteditems, archive, junkemail, outbox (404 skipped, cached per process) |
| ResolveFolder | alias: `GET /me/mailFolders/{alias}`; otherwise a case-insensitive displayName match in ListFolders | aliases accept spaces and case ("Sent Items"); "junk" means junkemail |
| ListMessages | `GET /me/mailFolders/{id}/messages?$top&$orderby=receivedDateTime desc&$select=...[&$filter=...]` | `$filter` conditions: `receivedDateTime ge <t>` first (epoch when no `--since`, to avoid InefficientFilter with `$orderby`), `isRead eq false`, `from/emailAddress/address eq '<addr>'`; limit default 25, max 1000 |
| SearchMessages | `GET /me/messages?$search="<text>"&$top&$select` (or per folder) | no `$orderby` or `$filter` with `$search`; relevance order |
| GetMessage | `GET /me/messages/{id}?$select=<summary>,body,ccRecipients,bccRecipients,internetMessageId,parentFolderId[,internetMessageHeaders]&$expand=attachments(...)` with `Prefer: outlook.body-content-type="text"` | a text body is returned; any other content type is treated as HTML. Internal senders may appear as X.500 addresses. `bccRecipients` is populated for drafts |
| ListAttachments / OpenAttachment | `GET /me/messages/{id}/attachments?$select=...`; content via `.../attachments/{aid}/$value` | metadata first (size known before download); `$value` streams raw bytes for file attachments |
| ListDrafts | `GET /me/mailFolders/drafts/messages?$orderby=lastModifiedDateTime desc` | the "drafts" alias works as a folder id |
| SendMail | `POST /me/sendMail {"message":{...},"saveToSentItems":true}` | 202 no body; custom headers must start with `x-`, and Graph limits their number; no `from` field is ever sent |
| CreateDraft / SendDraft / DeleteDraft | `POST /me/messages` (201 with id); `POST /me/messages/{id}/send` (202); `DELETE /me/messages/{id}` (204) | as stated |
| ReplyToSender | `POST /me/messages/{id}/reply {"message":{"internetMessageHeaders":[...]},"comment":"<body>"}` | 202; the comment is inserted above the quoted original and may be treated as HTML; the `message` parameter accepting headers is assumed. The subject prefix cannot be applied. No reply-all call exists |
| SetRead / MoveMessage | `PATCH /me/messages/{id} {"isRead":bool}` (200); `POST /me/messages/{id}/move {"destinationId":...}` (201, new id) | as stated |
| FindSentByKey | `GET /me/mailFolders/sentitems/messages?$filter=internetMessageHeaders/any(h:h/name eq '<hdr>' and h/value eq '<key>')&$top=1&$select=id` | filtering on `internetMessageHeaders` may be unsupported (HTTP 400, returned as a validation error that the use case treats as inconclusive); header is `X-Agent-Idempotency-Key` (the same constant the writer sets on the message); the probe is not run for draft send or reply, because `POST .../send` cannot add headers |

Error mapping assumptions: 400 validation (exit 9); 404 and 410 not_found (5); 409 and 412 conflict (7); other 4xx and 5xx general (1); 401, 403, 429, 502, 503, 504 come from core `httpx` (3, 4, 8). `Retry-After` is honoured on 429 and 503 for reads. Writes are never replayed. The send result is "not sent" (`domain.NotSent`) after local validation failure, any 4xx except 408, a second 401, 403, 429, or an auth or daemon failure; it is ambiguous (ledger entry stays pending, next attempt fails closed) after 408, any 5xx, timeouts, dropped connections and cancellation. A POST gets one 401 refresh-and-replay from `httpx` (the first 401 means the request was rejected before processing). `Page.NextPageToken` is the base64url of Graph's `@odata.nextLink`; a token not pointing at the configured host and `/me/` is a usage error (exit 2).

## Reference: policy semantics (loader and evaluation)

- Omitted bounds resolve to the PRD sample values in the loader (`policyfile.Default*`): `limits.max_writes_per_run` 20, `limits.max_results` 100, `read.max_body_bytes` 16000, `send.body.max_bytes` 20000, `read.html_to_text` and `read.defang_links` true. An explicit `0` for `max_writes_per_run` is honoured and denies all writes. Everything else omitted resolves to the denying value (send mode deny, external deny, no bcc, no reply-all, no attachments).
- The domain treats zero values as: `Recipients.MaxTotal <= 0` denies every send; `Send.Rate` zero means no limit; `Limits.MaxResults <= 0` falls back to 25.
- Every name in `send.content_filters` must exist in the filter map, otherwise the send is refused with rule `send.content_filter.<name>`; the loader rejects unknown names.
- `read.attachments` is `{download: deny}` or `{allow_types, max_bytes, out_dir}`; mixing is an error.

## Reference: ledger file format

`<path>` JSON `{"version":1,"entries":{"<key>":{"fingerprint","kind":"send|draft","status":"pending|sent|failed","at","ref_id","count"}}}` (an entry without `kind` is a send), directory 0700 and owned by the current user (checked on every locked operation; otherwise exit 1), file 0600, lock file `<path>.lock`, atomic temp, fsync and rename. A corrupt, unreadable or unknown-version file fails closed (error, nothing sent). Sent and failed entries older than 90 days are pruned on write; pending entries are never pruned. `Reserve` returns `new` for an unseen key and `pending` when it resets a failed key.
